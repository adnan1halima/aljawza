# نظام معلمي مسجد الجوزة (Al-Jawzah Mosque Teachers)

نظام ويب لمتابعة معلمي حلقات تحفيظ القرآن الكريم في **مسجد الجوزة**. كل معلم يدخل بحسابه الخاص ويرى طلابه فقط، ويسجّل حضورهم وتسميعهم وسلوكهم كل يوم سبت.

مبني بـ **Next.js 14 + TypeScript + Tailwind CSS + Supabase**، ويعمل بالكامل على الخطط المجانية (Supabase Free + Vercel Free)، وباللغة العربية واتجاه RTL، وقابل للتثبيت كتطبيق (PWA) على الجوال.

---

## 1) فكرة المشروع

- 12 حساب معلم (9 أسماء حقيقية + 3 خانات "أستاذ جديد" قابلة للتعديل لاحقًا).
- كل معلم يرى **طلابه فقط** بفضل Row Level Security في Supabase — لا يمكن لمعلم رؤية أو تعديل طلاب معلم آخر مهما حاول من الواجهة أو حتى بطلبات مباشرة لقاعدة البيانات.
- حد أقصى **65 طالبًا** لكل معلم (مطبّق في الواجهة وفي قاعدة البيانات).
- تسجيل حضور/غياب وتسميع وسلوك كل **يوم سبت فقط** (مطبّق في الواجهة وفي قاعدة البيانات عبر قيد `CHECK`).
- ترتيب تلقائي للطلاب حسب مجموع مقدار الحفظ، داخل حلقة كل معلم وعلى مستوى المسجد كله.

## 11-22) دليل الإعداد والنشر الكامل

### 13) طريقة إنشاء مشروع Supabase مجاني

1. اذهب إلى https://supabase.com وسجّل حسابًا مجانيًا.
2. اضغط **New Project**.
3. اختر اسمًا مثل `aljawzah-mosque`، وكلمة مرور لقاعدة البيانات (احفظها)، والمنطقة الأقرب لك.
4. انتظر دقيقتين حتى يجهز المشروع.

### إعداد قاعدة البيانات

1. من القائمة الجانبية اذهب إلى **SQL Editor**.
2. افتح ملف `supabase/schema.sql` من المشروع، انسخ محتواه بالكامل، الصقه في المحرر، ثم اضغط **Run**.
3. تأكد من عدم ظهور أي خطأ (يمكن تشغيله أكثر من مرة بأمان).

### 18) طريقة إنشاء حساب مستقل لكل معلم (12 حساب)

1. من القائمة الجانبية في Supabase اذهب إلى **Authentication > Users**.
2. اضغط **Add user > Create new user** لكل معلم من الـ 12، وأدخل:
   - بريدًا إلكترونيًا فريدًا لكل معلم، مثل: `malek@aljawzah.local`، `diaa@aljawzah.local`، إلخ.
   - كلمة مرور مؤقتة (شاركها مع المعلم بشكل خاص لاحقًا، ولا تعرضها داخل التطبيق).
   - في حقل **User Metadata** أضف: `{"name": "مالك طرابلسي"}` (اسم المعلم بالعربية) — سيُنشأ ملفه الشخصي تلقائيًا بهذا الاسم بفضل محفز قاعدة البيانات.
3. كرر الخطوة للأسماء التالية:
   1. مالك طرابلسي
   2. ضياء اللبابيدي
   3. يزن بوارشي
   4. ياسر الزبيبي
   5. فارس خضراوي
   6. عبد الله صمام
   7. علاء النجار
   8. أنس عرفة
   9. عدنان حليمة
   10. أستاذ جديد (1)
   11. أستاذ جديد (2)
   12. أستاذ جديد (3)

> إذا لم تحدد `name` عند الإنشاء، سيستخدم النظام تلقائيًا الجزء الأول من البريد الإلكتروني كاسم مؤقت — ويمكن تعديله لاحقًا من صفحة **الإعدادات** داخل التطبيق.

### 19) طريقة تغيير أسماء المعلمين الثلاثة الفارغة لاحقًا

الطريقة الأسهل: اطلب من صاحب الحساب تسجيل الدخول ثم الذهاب إلى **الإعدادات > اسم المعلم** وتعديله بنفسه.
أو من طرفك: **Table Editor > profiles** في Supabase، عدّل عمود `name` مباشرة لصف الحساب المطلوب.

### 14) طريقة ربط Supabase بالمشروع

1. من إعدادات مشروع Supabase اذهب إلى **Project Settings > API**.
2. انسخ **Project URL** و **anon public key**.
3. الصقهما في `.env.local`:
   ```
   NEXT_PUBLIC_SUPABASE_URL=... 
   NEXT_PUBLIC_SUPABASE_ANON_KEY=...
   ```

### 12) طريقة التشغيل على الكمبيوتر

```bash
npm install
npm run dev
```
افتح `http://localhost:3000` وسجّل الدخول بأحد حسابات المعلمين.

### 15) طريقة رفع المشروع إلى GitHub

```bash
git init
git add .
git commit -m "النسخة الأولى - نظام معلمي مسجد الجوزة"
git branch -M main

git push -u origin main
```
(أنشئ المستودع فارغًا من github.com أولًا، وضع رابطه بدل الرابط أعلاه)

### 16) طريقة نشره مجانًا على Vercel

1. سجّل الدخول إلى https://vercel.com بحساب GitHub.
2. اضغط **Add New > Project** واختر المستودع الذي رفعته.
3. في خطوة **Environment Variables** أضف نفس القيمتين من `.env.local`:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
4. اضغط **Deploy** وانتظر حتى ينتهي البناء.

### 17) طريقة إعطاء رابط التطبيق للمعلمين

بعد النشر سيعطيك Vercel رابطًا مثل: `https://aljawzah-mosque-teachers.vercel.app`
شارك هذا الرابط مع كل معلم، مع بريده الإلكتروني وكلمة المرور الخاصة به بشكل خاص (رسالة أو مكالمة، وليس بشكل علني).

### 21) طريقة تحويل الموقع إلى تطبيق يُثبّت على الجوال (PWA)

المشروع مهيأ مسبقًا بملفي `manifest.json` و `sw.js`. بعد فتح الرابط من متصفح الجوال (Chrome على أندرويد أو Safari على آيفون):
- **أندرويد (Chrome):** ستظهر رسالة "إضافة إلى الشاشة الرئيسية" تلقائيًا، أو من قائمة المتصفح ⋮ اختر **تثبيت التطبيق**.
- **آيفون (Safari):** اضغط زر المشاركة ⬆️ ثم **إضافة إلى الشاشة الرئيسية**.

### 20) طريقة اختبار إضافة طالب وتسجيل السبت والترتيب

1. سجّل الدخول بأحد حسابات المعلمين.
2. اضغط **+ إضافة طالب** وأدخل الاسم على الأقل، ثم احفظ.
3. من صفحة تفاصيل الطالب اضغط **تسجيل يوم السبت**، اختر تاريخ يوم سبت فعلي، أدخل مقدار الحفظ، واحفظ.
4. عد إلى قائمة الطلاب: سيظهر ترتيب الطالب تلقائيًا حسب مجموع مقدار الحفظ، وسيظهر أيضًا في صفحة تفاصيله ترتيبه داخل الحلقة وعلى مستوى المسجد.
5. لتجربة بيانات جاهزة مباشرة: نفّذ `supabase/seed.sql` بعد إنشاء حساب المعلم الأول (راجع التعليمات داخل الملف).

### 22) حدود وقيود الخطط المجانية

- **Supabase المجانية:** قاعدة بيانات حتى 500 ميجابايت، حتى 50,000 مستخدم شهريًا (Auth)، توقف مؤقت للمشروع بعد 7 أيام بدون نشاط (يُعاد تفعيله تلقائيًا عند أول زيارة، قد يستغرق دقيقة). هذا يكفي بسهولة لعدد طلاب مسجد واحد.
- **Vercel المجانية:** تكفي تمامًا لمشروع بحجم هذا التطبيق (استضافة + نشر تلقائي من GitHub)، مع حدود استخدام شهرية سخية لا يصل إليها تطبيق داخلي بهذا الحجم عادةً.
- لا حاجة لأي بطاقة ائتمان أو اشتراك مدفوع لتشغيل هذا المشروع بكامل ميزاته.

## تحديث: نظام النقاط الجديد + حساب المدير الشامل

تمت إضافة تحديث جديد على النظام، ملفه: **`supabase/migration_02_scoring_and_admin.sql`**

### كيف تطبّقه

1. من Supabase: **SQL Editor** → انسخ محتوى `supabase/migration_02_scoring_and_admin.sql` بالكامل والصقه واضغط **Run**.
2. الملف يفترض أن حساب أ. مالك طرابلسي بريده `malek@aljawzah.local`. إذا استخدمت بريدًا مختلفًا، عدّل هذا السطر داخل الملف **قبل التشغيل**:
   ```sql
   update public.profiles set is_admin = true where email = 'malek@aljawzah.local';
   ```
   وضع بريده الفعلي بدلها.

### جدول نقاط التسميع (عدد الصفحات × التقييم)

| عدد الصفحات \ التقييم | 1 | 2 | 3 |
|---|---|---|---|
| 1 | 3 | 4 | 5 |
| 2 | 5 | 8 | 11 |
| 3 | 9 | 13 | 17 |
| 4 | 13 | 18 | 23 |
| 5 | 14 | 20 | 26 |

هذا الجدول محصور بالقيم أعلاه فقط (عدد الصفحات 1-5، التقييم 1-3)، لذلك ظهرت هذي الحقول كأزرار اختيار وليس كحقل مفتوح، لضمان عدم إدخال قيمة خارج الجدول.

### حقول سجل يوم السبت الجديدة

- **عدد الصفحات** (1-5) و **التقييم** (1-3): يحسبان تلقائيًا "مجموع نقاط التسميع" حسب الجدول أعلاه.
- **اللباس الإسلامي**: 0 أو 1 أو 2 أو 3.
- **الالتزام بالأدب**: 0 أو 5 فقط.
- **الانضباط**: حقل حر اختياري، يقبل رقمًا موجبًا أو سالبًا (بونص أو خصم يدوي من المعلم).
- **مجموع نقاط اليوم** = مجموع نقاط التسميع + اللباس + الأدب + الانضباط (يُحسب تلقائيًا في قاعدة البيانات).

### حقول نقاط الطالب الجديدة (تظهر في صفحة تفاصيل الطالب)

- **النقاط السابقة**: مجموع نقاط كل الأيام المسجلة تلقائيًا (يتحدث لحظيًا مع كل تسجيل جديد).
- **النقاط الموزعة**: حقل حر يعدّله المعلم يدويًا في أي وقت (بونص أو خصم عام، مثل نقاط تحفيزية).
- **المجموع الكلي** = النقاط السابقة + النقاط الموزعة، وهو المستخدم في حساب **الترتيب** (داخل الحلقة وعلى مستوى المسجد).

### حساب المدير الشامل (أ. مالك طرابلسي)

بعد تشغيل ملف الترحيل، حساب أ. مالك (المحدد بالبريد أعلاه) يصير حسابًا **مديرًا**:
- يقدر يشوف قائمة كل المعلمين من قائمة منسدلة تظهر تلقائيًا أعلى الصفحة الرئيسية وقائمة الطلاب باسم **"عرض حساب المعلم"**.
- يختار أي معلم من القائمة، وتتغير كل الصفحة لتعرض بيانات ذاك المعلم فقط (طلابه، إحصائياته).
- يقدر يضيف طالبًا، يعدل، يحذف، ويسجل سبتًا لأي معلم يختاره — تمامًا كأنه داخل بحسابه.
- هذي الصلاحية محمية بالكامل من جهة قاعدة البيانات (RLS)، فلا يقدر أي معلم عادي غير أ. مالك الوصول لهذي الميزة حتى لو حاول تعديل الرابط يدويًا.

> ملاحظة: إذا احتجت لاحقًا تعطي صلاحية "مدير" لحساب ثاني، نفّذ في SQL Editor:
> ```sql
> update public.profiles set is_admin = true where email = 'بريد_الحساب@aljawzah.local';
> ```

## تحديث ثانٍ: حالة الطالب كل سبت + إحصائيات نهاية الملف

ملفه: **`supabase/migration_03_attendance_status.sql`** — نفّذه من SQL Editor بعد الملفين السابقين (schema.sql ثم migration_02).

### حالة الطالب ونقاطها

كل سبت، بدل "حاضر/غائب" فقط، صار فيه 4 حالات:

| الحالة | النقاط |
|---|---|
| حضور | 3+ |
| غياب | 5- |
| غياب مبرر | 0 |
| تأخر | 2- |

عند اختيار **حضور** أو **تأخر** تظهر حقول التسميع (الصفحات، التقييم، اللباس، الأدب، الانضباط، إلخ) ويُحسب مجموعها ضمن نقاط اليوم. عند اختيار **غياب** أو **غياب مبرر** تُخفى هذي الحقول تلقائيًا وتحتسب نقطة الحالة فقط.

**مجموع نقاط اليوم = نقاط الحالة + (نقاط التسميع + اللباس + الأدب + الانضباط، فقط إذا كان حضور أو تأخر).**

**المجموع الكلي للنقاط (الظاهر بصفحة الطالب) = مجموع نقاط كل أيام السبت المسجّلة للطالب تلقائيًا**، ويتحدّث لحظيًا مع كل تسجيل جديد.

### إحصائيات نهاية ملف الطالب

في أسفل صفحة كل طالب أضيف قسم **"إحصائيات الحضور خلال الدورة"** يعرض تلقائيًا (محسوبة من كل سجلات السبت المسجّلة للطالب طوال الدورة):
- عدد أيام الحضور
- عدد أيام الغياب
- عدد أيام التأخر
- عدد أيام الغياب المبرر

## ملاحظات أمنية مهمة

- كلمات المرور تُدار بالكامل عبر Supabase Auth (مشفّرة)، ولا يخزّنها هذا المشروع في أي جدول عادي.
- Row Level Security مفعّل على الجداول الثلاثة، بحيث لا يستطيع أي معلم رؤية أو تعديل بيانات معلم آخر حتى لو حاول ذلك عبر أدوات المطورين في المتصفح.
- سياسة التحديث في جدول `students` تمنع تغيير `teacher_id` لنقل طالب إلى معلم آخر.
- قيد فريد `(student_id, date)` يمنع تكرار سجل نفس الطالب في نفس التاريخ.
- قيد `CHECK` على العمود `date` يمنع إدخال أي تاريخ ليس يوم سبت.
